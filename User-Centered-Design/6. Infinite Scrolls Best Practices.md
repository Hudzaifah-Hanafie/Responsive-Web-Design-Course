# Best Practices for Designing Infinite Scroll

Infinite scrolling is a web design pattern that automatically adds more content as a user scrolls down a page. Instead of choosing a new page or pressing a button for every batch of results, the user can continue scrolling to discover more content.

Social media feeds are a familiar example: as you reach the bottom of the posts currently displayed, more posts appear.

This note explains how infinite scrolling works, how it compares with pagination, and several design practices that can make it easier to use.

---

## 1. What Is Infinite Scrolling?

With infinite scrolling, a page starts with a set of content items. As the user approaches the bottom of the page, the application loads or creates another set and adds it to the existing content.

The example below uses ten posts as its initial content. The comment indicates where additional posts can be added.

### HTML: Content Container

```html
<link rel="stylesheet" href="styles.css">

<div class="infinite-scroll">
  <div class="post">Post 1</div>
  <div class="post">Post 2</div>
  <div class="post">Post 3</div>
  <div class="post">Post 4</div>
  <div class="post">Post 5</div>
  <div class="post">Post 6</div>
  <div class="post">Post 7</div>
  <div class="post">Post 8</div>
  <div class="post">Post 9</div>
  <div class="post">Post 10</div>
  <!-- More posts will load here as the user scrolls down -->
</div>

<script src="index.js"></script>
```

The `.infinite-scroll` element is the container for all posts. Each `.post` element represents one item. The external CSS and JavaScript files style the content and implement the scrolling behavior.

### CSS: Basic Layout

```css
.infinite-scroll {
  display: flex;
  flex-direction: column;
  gap: 12px;
}

.post {
  padding: 12px;
  border: 1px solid #ccc;
  border-radius: 4px;
}
```

The container uses Flexbox to arrange posts vertically:

- `display: flex` enables Flexbox.
- `flex-direction: column` places posts in a column.
- `gap: 12px` adds space between posts.
- `padding`, `border`, and `border-radius` make each post easier to distinguish visually.

### JavaScript: Add Posts When the User Reaches the Bottom

```js
// Simulate loading more content as the user scrolls
window.addEventListener('scroll', () => {
  if (window.innerHeight + window.scrollY >= document.body.offsetHeight) {
    loadMorePosts();
  }
});

function loadMorePosts() {
  const container = document.querySelector('.infinite-scroll');

  for (let i = 0; i < 3; i++) {
    const post = document.createElement('div');
    post.className = 'post';
    post.textContent = `Post ${container.children.length + 1}`;
    container.appendChild(post);
  }
}
```

The code listens for the window's `scroll` event. It compares the bottom of the visible viewport with the document's height:

- `window.innerHeight` is the height of the visible browser viewport.
- `window.scrollY` is how far the page has been scrolled vertically.
- `document.body.offsetHeight` is the body's height.

When the viewport reaches the bottom, `loadMorePosts()` creates three new `.post` elements and appends them to the container. The next post number is based on the number of children already in the container.

> **Important:** This is a small demonstration using generated placeholder posts. A production application would normally request another batch of real content and should prevent repeated scroll events from triggering overlapping loads. It should also handle loading failures and the point at which no more content is available.

## 2. Infinite Scrolling vs. Pagination

Infinite scrolling is sometimes used as an alternative to **pagination**.

Pagination divides a large collection of content into separate pages. Users move between those pages with controls such as **Previous** and **Next**. Search results are a common example: a user can move from one page of results to another.

With infinite scrolling, more content is appended to the current page as the user scrolls, rather than requiring a click to move to a separate page.

| Approach | How it works | User action |
|---|---|---|
| Infinite scrolling | More items are appended to the current page as the user scrolls | Keep scrolling |
| Pagination | Content is divided into separate pages | Select a page or use navigation controls |

### Example: Pagination Markup

```html
<link rel="stylesheet" href="styles.css">

<div class="pagination">
  <div class="post">Post 1</div>
  <div class="post">Post 2</div>
  <div class="post">Post 3</div>
  <!-- More posts will be on the next pages -->
</div>

<div class="pagination-controls">
  <button class="prev" disabled>Previous</button>
  <button class="next">Next</button>
</div>

<script src="index.js"></script>
```

The `.pagination` container displays the posts for the current page. The navigation controls let the user move between pages. The Previous button starts disabled because the example begins on the first page.

### CSS: Style the Posts and Controls

```css
.pagination {
  display: flex;
  flex-direction: column;
  gap: 12px;
}

.post {
  padding: 12px;
  border: 1px solid #ccc;
  border-radius: 4px;
}

.pagination-controls {
  margin-top: 12px;
}

.pagination-controls button {
  padding: 8px 16px;
  margin-right: 8px;
}
```

The post styling is the same as in the infinite-scrolling example. The controls have extra spacing so they are visually separated from the posts.

### JavaScript: Render the Current Page

```js
let currentPage = 1;
const postsPerPage = 3;
const totalPosts = 9;
const totalPages = Math.ceil(totalPosts / postsPerPage);

const container = document.querySelector('.pagination');
const prevButton = document.querySelector('.prev');
const nextButton = document.querySelector('.next');

function renderPosts() {
  container.innerHTML = '';

  const start = (currentPage - 1) * postsPerPage;
  const end = start + postsPerPage;

  for (let i = start; i < end && i < totalPosts; i++) {
    const post = document.createElement('div');
    post.className = 'post';
    post.textContent = `Post ${i + 1}`;
    container.appendChild(post);
  }

  prevButton.disabled = currentPage === 1;
  nextButton.disabled = currentPage === totalPages;
}

prevButton.addEventListener('click', () => {
  if (currentPage > 1) {
    currentPage--;
    renderPosts();
  }
});

nextButton.addEventListener('click', () => {
  if (currentPage < totalPages) {
    currentPage++;
    renderPosts();
  }
});

renderPosts();
```

#### How the pagination code works

1. **Set the page information.** `currentPage` tracks the selected page, `postsPerPage` sets the number of posts per page, and `totalPages` is calculated with `Math.ceil()`.
2. **Calculate the range.** `(currentPage - 1) * postsPerPage` gives the zero-based starting index. The loop creates posts from that index up to, but not including, `end`.
3. **Render the posts.** `container.innerHTML = ''` clears the previous page before the new page is drawn.
4. **Update the controls.** Previous is disabled on the first page; Next is disabled on the last page.
5. **Respond to clicks.** Each button changes `currentPage` when movement in that direction is allowed, then calls `renderPosts()`.
6. **Show the first page.** The final `renderPosts()` call displays the initial three posts.

For example, with nine total posts and three posts per page, the user can navigate through three pages.

## 3. Best Practice: Provide a “Load More” Button

Even when a design uses infinite scrolling, a **Load More** button can give users more control over when additional content appears. Instead of loading content automatically at the bottom of the page, the interface can wait for the user to click the button.

### HTML

```html
<link rel="stylesheet" href="styles.css">

<div class="infinite-scroll">
  <div class="post">Post 1</div>
  <div class="post">Post 2</div>
  <div class="post">Post 3</div>
  <!-- More posts will load when the user clicks "Load More" -->
</div>

<button class="load-more">Load More</button>

<script src="index.js"></script>
```

### CSS

```css
.infinite-scroll {
  display: flex;
  flex-direction: column;
  gap: 12px;
}

.post {
  padding: 12px;
  border: 1px solid #ccc;
  border-radius: 4px;
}

.load-more {
  margin-top: 12px;
  padding: 8px 16px;
}
```

### JavaScript

```js
const loadMoreButton = document.querySelector('.load-more');
const container = document.querySelector('.infinite-scroll');

loadMoreButton.addEventListener('click', () => {
  loadMorePosts();
});

function loadMorePosts() {
  for (let i = 0; i < 3; i++) {
    const post = document.createElement('div');
    post.className = 'post';
    post.textContent = `Post ${container.children.length + 1}`;
    container.appendChild(post);
  }
}
```

When the button is clicked, the event listener calls `loadMorePosts()`. The function appends three posts to the existing container, using the current number of children to calculate each post's number.

**Why this helps:** Users can decide when they are ready to see more content instead of having more content appear automatically as they scroll.

## 4. Best Practice: Make Navigation Easier

A long feed can make it difficult for users to return to a previous point. Consider providing navigation that helps users move around without having to scroll through the entire page again.

### Back or “Back to Top” Button

A **Back to Top** button returns the user to the top of the results. The following example displays a button after the user has scrolled more than 400 pixels.

### HTML

```html
<link rel="stylesheet" href="styles.css">

<div class="infinite-scroll">
  <div class="post">Post 1</div>
  <div class="post">Post 2</div>
  <div class="post">Post 3</div>
  <div class="post">Post 4</div>
  <div class="post">Post 5</div>
  <div class="post">Post 6</div>
  <div class="post">Post 7</div>
  <div class="post">Post 8</div>
  <div class="post">Post 9</div>
  <div class="post">Post 10</div>
  <!-- More posts will load here as the user scrolls down -->
</div>

<div class="loading-indicator" style="display: none;">Loading...</div>

<button id="back-to-top" class="back-to-top">↑ Back to Top</button>

<script src="index.js"></script>
```

The loading indicator starts hidden. JavaScript will display it while more posts are being added.

### CSS

```css
.infinite-scroll {
  display: flex;
  flex-direction: column;
  gap: 12px;
}

.post {
  padding: 12px;
  border: 1px solid #ccc;
  border-radius: 4px;
}

.loading-indicator {
  margin-top: 12px;
  font-weight: bold;
}

.back-to-top {
  position: fixed;
  bottom: 30px;
  right: 30px;
  display: none;
  padding: 10px 15px;
  background-color: #007BFF;
  color: white;
  border: none;
  border-radius: 4px;
  cursor: pointer;
  font-size: 14px;
  box-shadow: 0 2px 6px rgba(0, 0, 0, 0.2);
}

.back-to-top:hover {
  background-color: #0056b3;
}
```

The button uses `position: fixed` so it stays in the same position relative to the viewport. It is initially hidden with `display: none`, and the hover rule changes its background color when the pointer is over it.

### JavaScript

```js
const container = document.querySelector('.infinite-scroll');
const loadingIndicator = document.querySelector('.loading-indicator');
const backToTopBtn = document.getElementById('back-to-top');

window.addEventListener('scroll', () => {
  if (window.scrollY > 400) {
    backToTopBtn.style.display = 'block';
  } else {
    backToTopBtn.style.display = 'none';
  }

  if (window.innerHeight + window.scrollY >= document.body.offsetHeight) {
    loadMorePosts();
  }
});

backToTopBtn.addEventListener('click', () => {
  window.scrollTo({ top: 0, behavior: 'smooth' });
});

function loadMorePosts() {
  loadingIndicator.style.display = 'block';

  setTimeout(() => {
    for (let i = 0; i < 3; i++) {
      const post = document.createElement('div');
      post.className = 'post';
      post.textContent = `Post ${container.children.length + 1}`;
      container.appendChild(post);
    }

    loadingIndicator.style.display = 'none';
  }, 1000);
}
```

#### How this example works

- **Show or hide the button:** When `window.scrollY` is greater than `400`, the button is shown. Otherwise, it is hidden.
- **Load more content at the bottom:** The scroll handler checks whether the viewport has reached the bottom of the document and calls `loadMorePosts()` when it has.
- **Return to the top:** Clicking the button calls `window.scrollTo()` with `top: 0` and `behavior: 'smooth'`, which scrolls upward smoothly.
- **Show a loading indicator:** `loadingIndicator.style.display = 'block'` makes the message visible while the simulated load is in progress.
- **Simulate a delay:** `setTimeout()` waits 1,000 milliseconds (one second) before adding three posts and hiding the indicator.

> **Implementation note:** This example demonstrates the idea, but the scroll handler can call `loadMorePosts()` repeatedly while the page remains at the bottom, including while the one-second timer is running. A real implementation should track whether a load is already in progress and avoid starting another load until the current one finishes.

### Back Button vs. Back to Top

These controls serve related but different purposes:

- A **Back** button may return the user to a previous page or browsing state.
- A **Back to Top** button takes the user to the top of the current page.

Choose the control that matches the navigation users need.

## 5. Best Practice: Show a Loading Indicator

When additional content is being loaded, make that state visible. Without feedback, users may think the page has stopped responding or that no more content is coming.

The previous example uses a simple text indicator:

```html
<div class="loading-indicator" style="display: none;">Loading...</div>
```

JavaScript displays it when loading begins:

```js
loadingIndicator.style.display = 'block';
```

After the example's delay and the addition of the new posts, it hides the indicator:

```js
loadingIndicator.style.display = 'none';
```

The one-second delay is simulated with `setTimeout()`. It stands in for the time a real request might take; it does not fetch data from a server.

**Practical principle:** The interface should communicate the current state clearly—for example, when content is loading, when loading has finished, and when no more results remain.

---

## 6. Best Practice: Keep the Footer Accessible

Infinite scrolling can keep extending the page, pushing the footer farther down as new content is appended. If the footer contains important information, make sure users still have a practical way to reach it.

Depending on the design, useful footer content may include navigation links or other important site information. The key point is to consider footer accessibility when choosing an infinite-scroll pattern, rather than treating the footer as an afterthought.

---

## 7. Practical Checklist

Use this checklist when designing or reviewing an infinite-scrolling interface.

- [ ] **User control:** Would a “Load More” button help users decide when additional content appears?
- [ ] **Navigation:** Can users return to the top or otherwise get back to a previous point easily?
- [ ] **Loading feedback:** Is there a clear indicator while more content is being loaded?
- [ ] **Footer access:** Can users reach important footer information?
- [ ] **Repeated loading:** Does the implementation prevent multiple loads from starting at once?
- [ ] **End of content:** Does the interface handle the situation where there are no more results to load?

The first four items reflect the design considerations discussed in the examples. The last two are practical implementation checks for making the demonstrated behavior more robust.

## Summary

| Concept | Meaning | Why it matters |
|---|---|---|
| Infinite scrolling | More content is added as the user scrolls down | Lets users browse a continuous feed |
| Pagination | Content is split into separate pages with navigation controls | Gives users explicit page-by-page navigation |
| Load More button | A button the user clicks to append another batch of content | Gives users more control over loading |
| Back to Top | A control that scrolls to the beginning of the current page | Makes long pages easier to navigate |
| Loading indicator | A visible signal that more content is being loaded | Helps users understand that the page is working |
| Accessible footer | Important footer information remains reachable | Prevents useful site information from being difficult to find |

## Key Takeaways

1. **Infinite scrolling** adds content to the current page as the user scrolls.
2. **Pagination** presents content in separate pages and uses controls such as Previous and Next.
3. A **Load More** button can give users more control over when they see additional content.
4. Long feeds benefit from navigation aids such as a **Back to Top** button.
5. A **loading indicator** communicates that more content is being loaded.
6. Important **footer content** should remain accessible.
7. The sample code demonstrates the basic interaction. A production implementation should also guard against repeated or overlapping loads and handle the end of the content.

## Mental Model

Think of an infinite-scroll page as a list that grows in batches:

```text
Initial posts
     |
     v
User scrolls down
     |
     v
Has the user reached the loading point?
     |
     +-- No --> Keep browsing
     |
     +-- Yes --> Show loading feedback
                    |
                    v
              Add another batch
                    |
                    v
              Continue browsing
```

The central design goal is not simply to keep adding content. It is to help users browse a long list while keeping them informed, in control, and able to navigate the page.
