# Progressive Disclosure

Progressive disclosure is a user-interface (UI) design pattern that shows people the information and controls they need for their current task, while keeping less frequently used details hidden until requested.

The goal is to **reduce cognitive load**: users can focus on the main task without having to process every available option at once.

For example, a page might show a product's image, name, and price first. A **More details** button can reveal specifications, benefits, or warranty information when someone wants to learn more.

## 1. Core Concept

### How It Works

Progressive disclosure separates information into two broad levels:

- **Primary information:** the key content or controls users need most often. Keep these visible.
- **Additional information:** secondary details or advanced options that users may need only sometimes. Reveal these when requested.

A common interaction looks like this:

1. Show the essential information.
2. Provide a clear control, such as **Show more details**.
3. Reveal the additional information when the user activates the control.
4. Let the user hide the information again when appropriate.

### Why It Matters

Showing every option at once can make an interface feel crowded and difficult to scan. Progressive disclosure can:

- Reduce visual clutter.
- Help users focus on the task at hand.
- Make complex interfaces feel more approachable.
- Let users choose when they want more detail.

> **Important:** Progressive disclosure should simplify access to information, not make important information hard to find. Keep essential information visible and make hidden content easy to discover.

## 2. Everyday Examples

### Google's Advanced Search

Most searches can be completed with a simple search field, so the main search page does not need to display every advanced setting.

When someone needs more control, they can open Google's advanced search options. The extra controls are available without being part of the default, everyday interface.

You can access the feature at [Google Advanced Search](https://google.com/advanced_search).

### Product Details in an Online Store

A store may initially display product images, names, and prices. When a user is interested in a particular item, they can open its page or choose **More details** to see additional information.

Showing every specification for every product in the initial list would make it harder to browse. Revealing details on demand keeps the list easier to scan.

## 3. Implementing Progressive Disclosure with HTML, CSS, and JavaScript

The following examples demonstrate the same basic pattern in a web page:

- **HTML** defines the content and controls.
- **CSS** styles the interface and hides or displays additional content.
- **JavaScript** responds to user interaction and updates the interface.

### 3.1 A Simple Expandable Details Panel

#### HTML

```html
<link rel="stylesheet" href="styles.css">

<div class="progressive-disclosure">
  <button
    id="show-details-btn"
    aria-expanded="false"
    aria-controls="extra-content"
  >
    Show More Details
  </button>

  <div id="extra-content" class="hidden" tabindex="-1">
    <p>
      Here are additional details that are revealed only when you want to see them.
      This keeps the interface clean and reduces cognitive load.
    </p>
  </div>
</div>

<script src="index.js"></script>
```

The HTML contains a button and a panel:

- `id="show-details-btn"` gives JavaScript a way to find the button.
- `id="extra-content"` identifies the panel that will be shown or hidden.
- `class="hidden"` marks the panel as hidden initially.
- `aria-expanded="false"` communicates that the panel is initially collapsed to assistive technology.
- `aria-controls="extra-content"` identifies the content controlled by the button.
- `tabindex="-1"` allows JavaScript to move keyboard focus to the panel when it opens.

#### CSS

```css
.progressive-disclosure {
  font-family: sans-serif;
  max-width: 400px;
  margin: 20px auto;
}

#show-details-btn {
  background-color: #007bff;
  border: none;
  color: white;
  padding: 10px 16px;
  font-size: 1rem;
  border-radius: 5px;
  cursor: pointer;
  transition: background-color 0.2s ease;
}

#show-details-btn:hover,
#show-details-btn:focus {
  background-color: #0056b3;
  outline: none;
}

.hidden {
  display: none;
}

#extra-content {
  margin-top: 15px;
  padding: 10px;
  background-color: #f7f9fcff;
  border: 1px solid #ddd;
  border-radius: 5px;
}
```

The `.hidden` class uses `display: none` to remove the panel from the visible layout until it is needed. The remaining rules control the panel's spacing and appearance and style the button.

#### JavaScript

```js
const btn = document.getElementById('show-details-btn');
const content = document.getElementById('extra-content');

btn.addEventListener('click', () => {
  const isHidden = content.classList.toggle('hidden');
  btn.setAttribute('aria-expanded', !isHidden);

  if (!isHidden) {
    content.focus();
  }
});
```

What happens when the button is clicked:

1. `getElementById()` finds the button and content panel.
2. `addEventListener('click', ...)` runs a function when the button is activated.
3. `classList.toggle('hidden')` adds the `hidden` class if it is absent, or removes it if it is present.
4. The return value is stored in `isHidden`, indicating whether the panel is now hidden.
5. `aria-expanded` is updated so its value reflects the panel's current state.
6. When the panel opens, `focus()` moves keyboard focus to it.

This is the basic pattern: **toggle the content, keep the accessibility state in sync, and give users a clear way to reveal the extra information.**

## 4. Example: Expandable Product Details

An online store can use progressive disclosure to keep a product list compact while still making product information available.

### HTML

```html
<link rel="stylesheet" href="styles.css">

<div class="product-list">
  <div class="product" tabindex="0" aria-expanded="false" aria-controls="details-1">
    <img src="https://placehold.co/150x150" alt="Example Product Image">

    <button class="details-btn" aria-label="Show more details for Product 1">
      More details
    </button>

    <div id="details-1" class="product-details hidden" tabindex="-1">
      <p><strong>Product 1:</strong> This is a great product with awesome features that you'll love.</p>
      <ul>
        <li>Feature A</li>
        <li>Feature B</li>
        <li>Feature C</li>
      </ul>
    </div>
  </div>

  <div class="product" tabindex="0" aria-expanded="false" aria-controls="details-2">
    <img src="https://placehold.co/150x150" alt="Example Product Image">

    <button class="details-btn" aria-label="Show more details for Product 2">
      More details
    </button>

    <div id="details-2" class="product-details hidden" tabindex="-1">
      <p><strong>Product 2:</strong> Another fantastic item with lots of benefits for your daily use.</p>
      <ul>
        <li>Benefit X</li>
        <li>Benefit Y</li>
        <li>Benefit Z</li>
      </ul>
    </div>
  </div>
</div>

<script src="index.js"></script>
```

Each product has its own details panel with a unique ID. The first product controls `details-1`, while the second controls `details-2`.

### CSS

```css
.product-list {
  font-family: sans-serif;
  display: flex;
  gap: 20px;
  max-width: 800px;
  margin: 20px auto;
  flex-wrap: wrap;
}

.product {
  border: 1px solid #ccc;
  border-radius: 8px;
  padding: 10px;
  width: 180px;
  box-shadow: 0 2px 6px rgba(0, 0, 0, 0.1);
  position: relative;
}

.product img {
  width: 100%;
  border-radius: 6px;
  cursor: pointer;
  display: block;
  margin-bottom: 8px;
}

.details-btn {
  background-color: #007bff;
  border: none;
  color: white;
  padding: 6px 12px;
  font-size: 0.9rem;
  border-radius: 5px;
  cursor: pointer;
  width: 100%;
  transition: background-color 0.3s ease;
}

.details-btn:hover,
.details-btn:focus {
  background-color: #0056b3;
  outline: none;
}

.product-details {
  margin-top: 10px;
  background-color: #f7f9fc;
  border: 1px solid #ddd;
  border-radius: 6px;
  padding: 8px;
  font-size: 0.9rem;
}

.hidden {
  display: none;
}
```

The `.product-list` uses Flexbox to arrange product cards with spacing between them. `flex-wrap: wrap` allows cards to move onto another row when there is not enough horizontal space.

The `.product-details` class styles the extra information, while `.hidden` keeps it out of the layout until the user asks to see it.

### JavaScript

```js
document.querySelectorAll('.details-btn').forEach(button => {
  button.addEventListener('click', () => {
    const product = button.closest('.product');
    const details = product.querySelector('.product-details');
    const isHidden = details.classList.toggle('hidden');

    product.setAttribute('aria-expanded', !isHidden);

    if (!isHidden) {
      details.focus();
      button.textContent = 'Hide details';
    } else {
      button.textContent = 'More details';
    }
  });
});
```

This example handles multiple product cards without writing a separate click handler for each one:

- `querySelectorAll('.details-btn')` selects every details button.
- `forEach()` attaches a click handler to each selected button.
- `button.closest('.product')` finds the product card containing the clicked button.
- `product.querySelector('.product-details')` finds the details panel inside that specific card.
- `classList.toggle('hidden')` opens or closes that panel.
- The button label changes to **Hide details** when the panel is open and returns to **More details** when it is closed.

The important idea is that each button operates on the details belonging to its own product card.

## 5. Best Practices for Progressive Disclosure

### 5.1 Keep Important Information Visible

Users should not have to open extra panels to find information that is essential to the task.

For example, an order summary should show the number of items and total price immediately. Less frequently used options, such as coupon codes or gift wrapping, can be placed behind an **Advanced Options** control.

#### HTML

```html
<link rel="stylesheet" href="styles.css">

<div class="info-section">
  <h2>Order Summary</h2>
  <p><strong>Items in Cart:</strong> 3</p>
  <p><strong>Total Price:</strong> $75.00</p>

  <div class="advanced-options">
    <button
      id="toggle-advanced-btn"
      aria-expanded="false"
      aria-controls="advanced-details"
    >
      Show Advanced Options
    </button>

    <div id="advanced-details" class="hidden" tabindex="-1">
      <p>Apply coupon codes, gift wrapping, or select shipping preferences here.</p>

      <form>
        <label for="coupon">Coupon Code:</label><br>
        <input type="text" id="coupon" name="coupon"><br><br>

        <label>
          <input type="checkbox" name="gift-wrap">
          Gift wrap this order
        </label><br><br>

        <label for="shipping">Shipping method:</label><br>
        <select id="shipping" name="shipping">
          <option value="standard">Standard (Free)</option>
          <option value="express">Express ($10.00)</option>
        </select>
      </form>
    </div>
  </div>
</div>

<script src="index.js"></script>
```

#### CSS

```css
.info-section {
  font-family: sans-serif;
  max-width: 400px;
  margin: 30px auto;
  border: 1px solid #ccc;
  padding: 20px;
  border-radius: 8px;
  background-color: #fff;
}

h2 {
  margin-top: 0;
}

.advanced-options {
  margin-top: 20px;
}

#toggle-advanced-btn {
  background-color: #007bff;
  color: white;
  border: none;
  padding: 10px 16px;
  font-size: 1rem;
  border-radius: 5px;
  cursor: pointer;
  transition: background-color 0.25s ease;
}

#toggle-advanced-btn:hover,
#toggle-advanced-btn:focus {
  background-color: #0056b3;
  outline: none;
}

.hidden {
  display: none;
}

#advanced-details {
  margin-top: 15px;
  padding: 15px;
  border: 1px solid #ddd;
  border-radius: 6px;
  background-color: #f7f9fc;
}
```

#### JavaScript

```js
const toggleBtn = document.getElementById('toggle-advanced-btn');
const advancedDetails = document.getElementById('advanced-details');

toggleBtn.addEventListener('click', () => {
  const isHidden = advancedDetails.classList.toggle('hidden');
  toggleBtn.setAttribute('aria-expanded', !isHidden);

  if (!isHidden) {
    advancedDetails.focus();
  }
});
```

The order's key information remains visible. The user can choose to open the additional options when they need them.

### 5.2 Provide a Clear, Consistent Access Point

Use an obvious control—such as a button or link—to reveal additional information. Keep it near the content it affects and label it clearly.

Avoid scattering several controls that appear to reveal the same information. Too many competing entry points can make the interface harder to understand.

#### HTML

```html
<link rel="stylesheet" href="styles.css">
<script src="index.js" defer></script>

<div class="product-preview">
  <img src="https://placehold.co/150x150" alt="Example Product Image">

  <h3>Sample Product</h3>
  <p class="price">$49.99</p>

  <button class="info-toggle" aria-expanded="false" aria-controls="product-info">
    More Info
  </button>

  <div id="product-info" class="product-info hidden" tabindex="-1">
    <p>
      This product is made from high-quality materials and comes with a 2-year warranty.
      Perfect for everyday use.
    </p>
    <ul>
      <li>Durable and lightweight</li>
      <li>Available in multiple colors</li>
      <li>Free shipping included</li>
    </ul>
  </div>
</div>
```

The button is the single, clear entry point for the extra product information. The `defer` attribute on the script tells the browser to run the script after the HTML has been parsed.

#### CSS

```css
body {
  font-family: sans-serif;
  padding: 30px;
  display: flex;
  justify-content: center;
}

.product-preview {
  max-width: 300px;
  border: 1px solid #ccc;
  padding: 16px;
  border-radius: 8px;
  background: #fff;
  text-align: center;
}

.product-preview img {
  width: 100%;
  border-radius: 4px;
  margin-bottom: 10px;
}

.price {
  font-weight: bold;
  color: #333;
  margin: 10px 0;
}

.info-toggle {
  background-color: #007bff;
  color: white;
  border: none;
  padding: 10px 16px;
  font-size: 1rem;
  border-radius: 5px;
  cursor: pointer;
  transition: background-color 0.2s ease;
}

.info-toggle:hover,
.info-toggle:focus {
  background-color: #0056b3;
  outline: none;
}

.product-info {
  margin-top: 15px;
  text-align: left;
  background-color: #f9f9f9;
  border: 1px solid #ddd;
  padding: 12px;
  border-radius: 6px;
}

.hidden {
  display: none;
}
```

#### JavaScript

```js
const toggleBtn = document.querySelector('.info-toggle');
const infoPanel = document.getElementById('product-info');

toggleBtn.addEventListener('click', () => {
  const isHidden = infoPanel.classList.toggle('hidden');

  toggleBtn.setAttribute('aria-expanded', !isHidden);
  toggleBtn.textContent = isHidden ? 'More Info' : 'Hide Info';

  if (!isHidden) {
    infoPanel.focus();
  }
});
```

This version updates both the accessibility state and the button's visible label. Users can tell whether the next action will open or close the panel.

### 5.3 Keep the Interaction Understandable

A good progressive-disclosure interaction should make three things clear:

- **What is hidden?** The label should describe the content or options the user can reveal.
- **How do I reveal it?** Use a familiar, easy-to-find control.
- **How do I close it again?** Make the control's behavior and label clear when the content is open.

For accessibility, use semantic controls such as `<button>` for actions and keep attributes such as `aria-expanded` synchronized with the actual state of the panel.

## 6. Common Implementation Ideas

| HTML, CSS, or JavaScript feature | Purpose in these examples |
|---|---|
| `class="hidden"` | Marks content that should initially be hidden. |
| `display: none` | Removes hidden content from the visible layout. |
| `addEventListener('click', ...)` | Runs code when a user activates a control. |
| `classList.toggle('hidden')` | Alternates between hidden and visible states. |
| `aria-expanded` | Communicates whether the controlled content is expanded. |
| `aria-controls` | Identifies the element controlled by a button. |
| `tabindex="-1"` and `.focus()` | Allow focus to move to a revealed panel. |
| `querySelectorAll()` and `forEach()` | Attach similar behavior to multiple elements. |
| `closest()` | Finds the nearest containing element that matches a selector. |

> **Implementation note:** The examples are learning demonstrations, not complete production-ready components. In a production interface, also check keyboard behavior, visible focus indicators, and accessibility with assistive technologies. For example, removing the default outline without providing a clear replacement can make keyboard focus harder to see.

## Summary

| Principle | What to do |
|---|---|
| Show essentials first | Keep the most important information and controls visible. |
| Reveal secondary details on demand | Put less frequently used options behind a clear control. |
| Reduce cognitive load | Avoid overwhelming users with every detail at once. |
| Make controls obvious | Use clear labels such as **Show More Details** or **Advanced Options**. |
| Keep state synchronized | Update the content's visibility, button label, and `aria-expanded` value together. |
| Consider accessibility | Use semantic buttons and make focus and expanded state understandable. |

## Key Takeaways

- **Progressive disclosure shows users what they need now and reveals additional information when they ask for it.**
- It is useful when an interface contains many details or advanced options that not everyone needs all the time.
- It should reduce clutter without hiding information users need to complete their task.
- A clear control, predictable behavior, and consistent accessibility state help users understand the interaction.
- The same pattern can be used for simple details panels, product cards, order forms, and advanced search options.

## Mental Model

Think of progressive disclosure as an interface with layers:

```text
Essential information
        |
        v
Clear control (e.g., "Show more")
        |
        v
Additional details or advanced options
        |
        v
User can hide the extra information again
```

**Keep the essentials in view; reveal the rest when it becomes relevant.**
