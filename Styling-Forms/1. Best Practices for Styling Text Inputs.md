# Best Practices for Styling Text Inputs

Text inputs are a small part of a form, but their styling has a direct effect on **readability, accessibility, and usability**. A well-styled input should make its purpose clear, keep its text readable, respond visibly to keyboard focus, and communicate validation errors without confusing them with other states.

This note covers five practical areas:

1. Readable text and sufficient contrast
2. Clear, readable placeholders
3. Flexible sizing and user-controlled resizing
4. Visible focus indicators
5. Distinguishable validation-error states

## 1. Start with Accessible, Readable Inputs

As with any text element, an input needs text that is large enough to read and colors that contrast sufficiently with the background.

A useful starting point is to style the page, form, label, and input together. The example below uses a visible label, a comfortable font size, a clear border, and a white input background.

### Example: A basic text input

**HTML**

```html
<link rel="stylesheet" href="styles.css">

<form class="accessible-form">
  <label for="username">Username</label>
  <input type="text" id="username" name="username" placeholder="Enter your username">
  <button type="submit">Submit</button>
</form>
```

**CSS**

```css
body {
  background-color: #f9fafb;
  color: #222;
  padding: 2rem;
}

.accessible-form {
  max-width: 320px;
  margin: 0 auto;
}

label {
  display: block;
  font-weight: 600;
  margin-bottom: 0.5rem;
}

input[type="text"] {
  width: 100%;
  padding: 0.6rem 0.8rem;
  font-size: 1rem;
  border: 2px solid #555;
  border-radius: 4px;
  background-color: #fff;
  color: #111;
}

input[type="text"]:focus {
  outline: 3px solid #1e90ff;
  border-color: #1e90ff;
}

button {
  margin-top: 1rem;
  padding: 0.6rem 1rem;
  font-size: 1rem;
  background-color: #1e90ff;
  color: #fff;
  border: none;
  border-radius: 4px;
  cursor: pointer;
}

button:hover,
button:focus {
  background-color: #187bcd;
}
```

**What to notice**

- `font-size: 1rem` gives the input text a readable size.
- `color: #111` sets the text color, while `background-color: #fff` sets the field background.
- `border: 2px solid #555` makes the input boundary visible.
- The label is a separate, visible description of the field. Its `for` value matches the input's `id`.

### Visual explanation

The label identifies the field, the input area is where the user types, and the placeholder offers an example or hint. These parts have different jobs; placeholder text should not replace the label.

## 2. Make Placeholder Text Readable

The placeholder is often overlooked because it is not the text the user enters. However, **placeholder text is still text**, so it also needs sufficient contrast to remain readable.

The `::placeholder` pseudo-element lets you style it separately from the text entered by the user. For example:

### Example: An email input with a styled placeholder

**HTML**

```html
<link rel="stylesheet" href="styles.css">

<form class="accessible-form">
  <label for="email">Email address</label>
  <input type="email" id="email" name="email" placeholder="you@example.com">
  <button type="submit">Submit</button>
</form>
```

**CSS**

```css
body {
  background-color: #f9fafb;
  color: #222;
  padding: 2rem;
}

.accessible-form {
  max-width: 320px;
  margin: 0 auto;
}

label {
  display: block;
  font-weight: 600;
  margin-bottom: 0.5rem;
}

input[type="email"] {
  width: 100%;
  padding: 0.6rem 0.8rem;
  font-size: 1rem;
  border: 2px solid #555;
  border-radius: 4px;
  background-color: #fff;
  color: #111;
}

input[type="email"]::placeholder {
  color: #555;
  opacity: 1;
  font-style: italic;
}

input[type="email"]:focus {
  outline: 3px solid #1e90ff;
  border-color: #1e90ff;
}

button {
  margin-top: 1rem;
  padding: 0.6rem 1rem;
  font-size: 1rem;
  background-color: #1e90ff;
  color: #fff;
  border: none;
  border-radius: 4px;
  cursor: pointer;
}

button:hover,
button:focus {
  background-color: #187bcd;
}
```

**What to notice**

- `input[type="email"]::placeholder` targets only the placeholder in email inputs.
- `color: #555` gives the placeholder a darker gray.
- `opacity: 1` prevents the browser's default placeholder transparency from making it too faint.
- `font-style: italic` distinguishes the hint visually. This is optional; readability is the important part.

> **Remember:** A placeholder is a hint, not a substitute for a persistent label. The label remains available when the user starts typing and when the placeholder disappears.

## 3. Let Users Adapt the Input

An input should not unnecessarily restrict how users interact with it.

For a `textarea`, avoid removing the browser's resize handle if users may need more room to write. The example uses `resize: both`, which allows the user to resize the field horizontally and vertically.

The field should also scale with page zoom. Relative sizing such as `rem`, along with a flexible width, helps the layout adapt instead of relying entirely on fixed dimensions.

### Example: A resizable message field

**HTML**

```html
<link rel="stylesheet" href="styles.css">

<form class="accessible-form">
  <label for="message">Your message</label>
  <textarea id="message" name="message" placeholder="Type your message here..."></textarea>
  <button type="submit">Send</button>
</form>
```

**CSS**

```css
body {
  background-color: #f9fafb;
  color: #222;
  padding: 2rem;
  line-height: 1.5;
}

.accessible-form {
  max-width: 480px;
  margin: 0 auto;
}

label {
  display: block;
  font-weight: 600;
  margin-bottom: 0.5rem;
}

textarea {
  width: 100%;
  min-height: 120px;
  padding: 0.8rem;
  font-size: 1rem;
  border: 2px solid #555;
  border-radius: 4px;
  background-color: #fff;
  color: #111;
  resize: both;
  box-sizing: border-box;
}

textarea::placeholder {
  color: #555;
  opacity: 1;
}

textarea:focus {
  outline: 3px solid #1e90ff;
  border-color: #1e90ff;
}

button {
  margin-top: 1rem;
  padding: 0.6rem 1rem;
  font-size: 1rem;
  background-color: #1e90ff;
  color: #fff;
  border: none;
  border-radius: 4px;
  cursor: pointer;
}

button:hover,
button:focus {
  background-color: #187bcd;
}
```

**What to notice**

- `min-height: 120px` provides a useful starting height without defining an unchangeable height.
- `resize: both` preserves horizontal and vertical resizing. Use the resize behavior that suits the field; do not disable resizing without a reason.
- `box-sizing: border-box` makes the declared `width` include padding and borders, helping the field fit its container.
- `font-size: 1rem` and other relative units help the design respond to text scaling and page zoom.

## 4. Preserve a Clear Focus Indicator

Inputs can receive keyboard focus. When a user tabs into a field, the design should make it obvious which field is active.

A visible focus indicator can use a stronger border, an outline, or a surrounding `box-shadow`. Do not remove the browser's focus outline unless you replace it with another indicator that is at least as noticeable.

### Example: Focus styling across multiple inputs

**HTML**

```html
<link rel="stylesheet" href="styles.css">

<form class="accessible-form">
  <label for="name">Full name</label>
  <input type="text" id="name" name="name" placeholder="Enter your full name">

  <label for="email">Email address</label>
  <input type="email" id="email" name="email" placeholder="you@example.com">

  <button type="submit">Submit</button>
</form>
```

**CSS**

```css
body {
  background-color: #f9fafb;
  color: #222;
  padding: 2rem;
}

.accessible-form {
  max-width: 360px;
  margin: 0 auto;
}

label {
  display: block;
  font-weight: 600;
  margin-top: 1rem;
  margin-bottom: 0.5rem;
}

input[type="text"],
input[type="email"] {
  width: 100%;
  padding: 0.6rem 0.8rem;
  font-size: 1rem;
  border: 2px solid #666;
  border-radius: 4px;
  background-color: #fff;
  color: #111;
  transition: border-color 0.2s, box-shadow 0.2s;
}

input::placeholder {
  color: #555;
  opacity: 1;
}

input:focus {
  border-color: #1e90ff;
  box-shadow: 0 0 0 3px rgba(30, 144, 255, 0.4);
  outline: none;
}

button {
  margin-top: 1.5rem;
  padding: 0.6rem 1rem;
  font-size: 1rem;
  background-color: #1e90ff;
  color: #fff;
  border: none;
  border-radius: 4px;
  cursor: pointer;
}

button:hover,
button:focus {
  background-color: #187bcd;
}
```

**What to notice**

- `:focus` applies styles while the input has focus.
- The blue border and `box-shadow` create a noticeable focus treatment.
- `outline: none` is used here only because the example replaces the default outline with a visible box shadow. Removing the outline without a replacement would make keyboard focus harder to see.
- `transition` makes the border and shadow changes gradual; it does not replace the focus indicator itself.

## 5. Make Validation Errors Distinct from Focus

A form also needs an error state for input that does not pass validation. The visual treatment should tell the user that something is wrong.

An error indicator must remain noticeable and must not look like the focus indicator. In the example below, the error state uses a red border and a pale red background, while focus uses a surrounding shadow. The error message is associated with the input through `aria-describedby`.

The original example shows the error message in the HTML. To make it update dynamically as the user types or validation runs, JavaScript is needed.

### Example: An email field with an error state

**HTML**

```html
<link rel="stylesheet" href="styles.css">

<form class="accessible-form">
  <label for="email">Email address</label>
  <input
    type="email"
    id="email"
    name="email"
    placeholder="you@example.com"
    aria-describedby="email-error"
  >
  <p id="email-error" class="error-message">
    Please enter a valid email address.
  </p>

  <button type="submit">Submit</button>
</form>

<script src="index.js"></script>
```

**CSS**

```css
body {
  background-color: #f9fafb;
  color: #222;
  padding: 2rem;
  font-family: system-ui, sans-serif;
}

.accessible-form {
  max-width: 360px;
  margin: 0 auto;
}

label {
  display: block;
  font-weight: 600;
  margin-bottom: 0.5rem;
}

input[type="email"] {
  width: 100%;
  padding: 0.6rem 0.8rem;
  font-size: 1rem;
  border: 2px solid #666;
  border-radius: 4px;
  background-color: #fff;
  color: #111;
  transition: border-color 0.2s, box-shadow 0.2s;
}

input::placeholder {
  color: #555;
  opacity: 1;
}

input:focus {
  border-color: #1e90ff;
  box-shadow: 0 0 0 3px rgba(30, 144, 255, 0.4);
  outline: none;
}

input.error {
  border-color: #d93025;
  background-color: #fff5f5;
}

input.error:focus {
  border-color: #d93025;
  box-shadow: 0 0 0 3px rgba(217, 48, 37, 0.4);
}

.error-message {
  color: #d93025;
  font-size: 0.95rem;
  margin-top: 0.4rem;
}

button {
  margin-top: 1.5rem;
  padding: 0.6rem 1rem;
  font-size: 1rem;
  background-color: #1e90ff;
  color: #fff;
  border: none;
  border-radius: 4px;
  cursor: pointer;
}

button:hover,
button:focus {
  background-color: #187bcd;
}
```

**What to notice**

- `.error` marks an input that has failed validation.
- The red border and pale red background communicate the error state.
- `.error-message` styles the explanatory text below the field.
- `aria-describedby="email-error"` associates the input with the paragraph whose `id` is `email-error`.
- `input.error:focus` keeps the error treatment while adding a focus shadow. This helps communicate both states without making them look identical.
- JavaScript would be responsible for adding or removing the `error` class and updating the message when validation changes.

### Visual explanation: Focus and error are different states

![[02-Focus-and-Error-States.excalidraw]]

Focus answers **“Where is the user working right now?”** Error answers **“What needs to be corrected?”** A field can be both focused and invalid, so the styling should communicate both at once.

## Summary

| Best practice | What to do | CSS / HTML to remember |
|---|---|---|
| Readable input text | Use an adequately sized font and sufficient text/background contrast | `font-size`, `color`, `background-color` |
| Visible field boundary | Give the input a clear border | `border` |
| Readable placeholder | Style placeholder text so it remains legible | `::placeholder`, `color`, `opacity` |
| User control | Allow a `textarea` to be resized when appropriate | `resize: both` |
| Adaptable sizing | Use flexible widths and relative sizing; account for padding and borders | `width`, `rem`, `box-sizing` |
| Keyboard focus | Keep a noticeable focus indicator | `:focus`, `outline`, `box-shadow` |
| Validation feedback | Make errors visually distinct and provide an associated message | `.error`, `.error-message`, `aria-describedby` |

## Key Takeaways

- Text inside an input and its placeholder both need to be readable.
- A visible label identifies the field; a placeholder is only a hint.
- Do not unnecessarily prevent users from resizing a `textarea`.
- Design inputs to adapt when users zoom the page.
- Keyboard focus must always have a noticeable visual indicator.
- Validation errors need their own clear visual treatment and explanatory message.
- Focus and error are not mutually exclusive: an invalid field may also be focused.
- Use JavaScript when the error message and error class need to change dynamically.

## Mental Model

Think of a text field as having **content and interaction states**:

- **Content guidance:** label and placeholder help the user understand what to enter.
- **Input area:** readable text, sufficient space, and adaptable sizing support entry.
- **Interaction feedback:** focus shows the current location; error shows what needs attention.

The styling is successful when the user can understand the field, enter information comfortably, and recognize its state without relying on guesswork.
