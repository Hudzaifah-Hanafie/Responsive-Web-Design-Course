# CSS `appearance: none`: When and Why to Use It

`appearance: none` is useful when a browser's built-in styling gets in the way of a custom design for form controls.

It removes the control's native visual appearance so that you can create your own appearance with CSS. This is especially relevant to **checkboxes**, **radio buttons**, and **search inputs**.

The important trade-off is that taking control of the visuals also means you must make sure important interaction feedback—especially focus and error indicators—is still visible.

## 1. The Problem: Browsers Style Form Controls for You

Browsers apply default styling to many HTML elements. Form controls such as checkboxes and search inputs are not always as flexible to style as ordinary elements.

For example:

- A checkbox normally has a browser-provided indicator.
- WebKit-based browsers can show a built-in search icon and cancel button for search inputs.
- These browser-provided details may not match the visual design you want.

This can make it difficult to create a consistent appearance across browsers and platforms.

## 2. What `appearance: none` Does

The CSS property `appearance` controls the native visual appearance of an element.

```css
input {
  appearance: none;
}
```

Setting it to `none` hides the native appearance of the control. You can then use ordinary CSS properties, pseudo-classes, and pseudo-elements to create a custom design.

**Important:** `appearance: none` changes the visual presentation; it does not mean that you should remove the control's interactive behavior. The control still needs clear visual feedback for its states.

### When It Is Useful

| Situation | Why `appearance: none` can help |
|---|---|
| Custom checkbox | Hide the browser's default checkbox indicator and draw your own checked/unchecked appearance. |
| Custom radio button | Remove the native appearance when you need to create a custom visual design. |
| Search input | Hide browser-provided search decorations, such as the icon and cancel button shown by WebKit-based browsers, so you can provide your own design. |
| Consistent cross-platform styling | Reduce differences caused by browser-provided visual styling. |

## 3. Example: Build a Custom Checkbox

The following example hides the native checkbox appearance and creates a custom square. When the checkbox is checked, it changes to green and displays a white tick.

### HTML

```html
<link rel="stylesheet" href="styles.css" />
<form>
  <label>
    <input class="checkbox" type="checkbox" /> Agree
  </label>
</form>
```

The checkbox is still a real HTML `input` element with `type="checkbox"`. The `label` contains it and the text `Agree`.

### CSS

```css
.checkbox {
  appearance: none;
  width: 18px;
  height: 18px;
  border: 2px solid #ccc;
  border-radius: 4px;
  display: inline-block;
  position: relative;
  cursor: pointer;
  transition: all 0.25s ease;
  vertical-align: middle;
}

.checkbox:hover {
  border-color: #888;
}

.checkbox:checked {
  background-color: #4caf50;
  border-color: #4caf50;
}

.checkbox:checked::after {
  content: "";
  position: absolute;
  left: 4px;
  top: 0px;
  width: 5px;
  height: 10px;
  border: solid white;
  border-width: 0 2px 2px 0;
  transform: rotate(45deg);
}

.checkbox:focus {
  outline: 2px solid #90caf9;
  outline-offset: 2px;
}
```

### How the CSS Works

| Rule | Purpose |
|---|---|
| `appearance: none` | Hides the browser's native checkbox appearance. |
| `width` and `height` | Set the custom checkbox dimensions to `18px × 18px`. |
| `border` and `border-radius` | Draw the unchecked box with a light-grey border and slightly rounded corners. |
| `display: inline-block` | Allows the checkbox to sit inline with the label text while accepting dimensions. |
| `position: relative` | Establishes the positioning context for the tick created by `::after`. |
| `cursor: pointer` | Shows a pointer cursor when hovering over the checkbox. |
| `transition` | Adds a short transition when CSS properties change. |
| `vertical-align: middle` | Aligns the checkbox more neatly with the text beside it. |
| `.checkbox:hover` | Darkens the border while the pointer is over the checkbox. |
| `.checkbox:checked` | Changes the background and border to green when checked. |
| `.checkbox:checked::after` | Creates the tick only when the checkbox is checked. |
| `.checkbox:focus` | Adds a visible outline when the checkbox receives focus. |

### How the Tick Is Drawn

The tick is not an image. It is a CSS pseudo-element created with `.checkbox:checked::after`.

Its border is drawn only on the bottom and right sides:

```css
border-width: 0 2px 2px 0;
```

Rotating that shape by `45deg` makes it look like a check mark.

The unchecked state shows only the custom box. The checked state adds the tick and changes the box to green.

## 4. Important: Do Not Lose Interaction Feedback

`appearance: none` gives you much more control over styling, but it also means you must take responsibility for visual details that the browser's default appearance may have provided.

In particular, make sure important states remain visible:

- **Focus:** users need to be able to tell when a control has keyboard or other focus. The example provides an outline with `:focus`.
- **Error:** if your form uses error indicators, make sure your custom styling does not make them disappear.
- **Checked state:** a custom checkbox should make its checked and unchecked states distinguishable.

The example's `:focus` rule is important. Without a visible focus treatment, the custom design could hide an important interaction cue.

> **Key principle:** Customize the appearance, but preserve the feedback that helps people understand and operate the control.

## 5. WebKit and Search Inputs

**WebKit** is a software engine used by web browsers to display websites. Safari is an example of a browser that uses WebKit.

For search inputs, WebKit-based browsers can display browser-provided details such as:

- A default search icon.
- A cancel button.

If those built-in details do not fit your design, `appearance: none` can hide them so that you can create your own indicators. This can help make the search input look consistent across browsers.

The source material does not provide a complete custom search-input code example, so the checkbox example above is the concrete implementation to follow.

## 6. Practical Reasons to Use It

Beyond matching a visual design, custom styling can help with practical interface goals:

- **Consistent cross-platform styling:** create a more uniform appearance instead of relying on each browser's default control styling.
- **Larger mobile tap targets:** size a custom control so it is easier to tap on a mobile device.
- **Sufficient color contrast:** choose colors that make the checkbox states easier to distinguish.

These benefits depend on the custom styles you create. `appearance: none` itself does not automatically make a control easier to use; it gives you the control needed to design it that way.

## Summary

| Concept | Remember |
|---|---|
| Browser default styling | Browsers provide their own appearance for many form controls. |
| `appearance: none` | Hides the native visual appearance so CSS can provide a custom one. |
| Checkbox styling | Use CSS dimensions, borders, pseudo-classes, and pseudo-elements to create custom states. |
| Search input styling | Can hide WebKit-provided search decorations such as the search icon and cancel button. |
| Focus and error feedback | Must remain visible and understandable after customizing the control. |
| Practical benefits | Can support consistent styling, larger mobile tap targets, and better color contrast. |

## Key Takeaways

1. Use `appearance: none` when browser-provided form-control styling prevents you from achieving the design you need.
2. It is particularly useful for custom checkboxes, radio buttons, and search inputs.
3. After removing the native appearance, build the visual states yourself with CSS.
4. Do not forget focus and error indicators. Custom styling should not remove important interaction feedback.
5. Use it for a reason; if the native appearance already works for your design, there may be no need to replace it.

## Mental Model

**The browser supplies the default look. `appearance: none` removes that look. Your CSS supplies the replacement.**

You gain visual control, and with that control comes the responsibility to make every important state clear.
