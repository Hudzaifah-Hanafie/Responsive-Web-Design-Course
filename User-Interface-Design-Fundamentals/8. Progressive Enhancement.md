# Progressive Enhancement

Progressive enhancement is a web design and development approach that makes sure an application’s **essential content and basic functionality work for as many users as possible**, regardless of their browser, device, or internet connection.

The idea is to start with a reliable core experience, then add improvements for browsers and environments that support them. Users with more capable browsers or faster connections can benefit from extra features, while users in less capable environments can still access the essentials.

---

## 1. Core Concept

A progressively enhanced application does not make its essential content depend on advanced features being available. Instead, it provides the core experience first and layers enhancements on top.

Think of it as building in layers:

1. **Core content and functionality** — the information and basic interactions users need.
2. **Presentation enhancements** — improved layouts and visual styling.
3. **Functional enhancements** — additional interactions or capabilities where supported.

The goal is not to make every browser display an identical experience. It is to make sure that differences in browser capabilities do not unnecessarily prevent people from using the application.

## 2. Core Principles

Progressive enhancement follows several practical principles:

- **Keep core content and basic functionality broadly accessible.** Essential information should not disappear just because a browser lacks support for a newer feature.
- **Use external CSS stylesheets for advanced layouts.** CSS can improve the presentation while keeping the underlying content available.
- **Use external JavaScript files for advanced functionality.** Add richer behavior without making the essential experience depend entirely on JavaScript where that dependency can be avoided.
- **Respect users’ browser preferences.** Do not assume every user has the same settings or wants the same presentation and behavior.

These principles help separate the content a user needs from optional improvements.

## 3. Why Progressive Enhancement Matters

### Accessibility and resilience

If essential content and functionality are available in the core experience, unsupported browser features are less likely to block users completely. This makes an application more resilient across different browsers and devices.

### Performance and slower connections

A progressively enhanced site can make its essential content available before the browser downloads optional resources. Users on slower connections may therefore be able to access the important information without waiting for every enhancement to load.

This does not automatically make every progressively enhanced site fast; performance still depends on how the page and its resources are built. The principle is to avoid making the basic experience wait unnecessarily for nonessential resources.

### Search engine optimization (SEO)

When the core content is present in the initial HTML response, search engines can more readily crawl that content without relying on JavaScript to generate it first. This can help a page’s discoverability.

## 4. Progressive Enhancement and JavaScript-Heavy Applications

Progressive enhancement can be challenging for applications whose essential functionality relies heavily on JavaScript. In those cases, providing a useful core experience without JavaScript may not always be practical.

Even so, the underlying principle remains valuable: make as much essential content and functionality available as reasonably possible, and avoid making users depend on features their environment may not support when there is a workable alternative.

## 5. Summary

| Area | Main idea |
|---|---|
| Core experience | Essential content and basic functionality should work broadly. |
| CSS | Use stylesheets to add improved layouts and presentation. |
| JavaScript | Add advanced behavior without unnecessarily blocking the essentials. |
| User preferences | Respect browser settings and preferences. |
| Accessibility | Reduce the chance that unsupported features prevent access. |
| Performance | Let users access core content without waiting for every optional resource. |
| SEO | Content in the initial HTML response is easier for search engines to crawl. |
| Limitations | A fully independent core experience may be difficult for JavaScript-heavy applications. |

## Key Takeaways

- **Start with the essentials, then add enhancements.**
- Keep core content and basic functionality as independent as reasonably possible from advanced browser features.
- Use CSS and JavaScript to improve the experience rather than unnecessarily blocking access to the basics.
- Progressive enhancement can support accessibility, performance, and SEO, but it is not an automatic guarantee of any of them.
- For JavaScript-heavy applications, apply the principle pragmatically according to what the application needs to do.

## Mental Model

Imagine a website as a layered experience:

```text
Core HTML content and basic functionality
                  |
                  v
        CSS presentation enhancements
                  |
                  v
      JavaScript behavior enhancements
```

The core layer should remain useful on its own wherever practical. Each additional layer improves the experience for environments that support it, rather than being the only way to access essential content.
