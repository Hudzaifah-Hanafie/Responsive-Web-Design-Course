# How Does the Cascade Algorithm Work at a High Level?

The **CSS Cascade Algorithm** is the process a browser uses to decide which CSS rule should be applied when multiple rules target the same element.

It evaluates applicable rules through several stages:

1. **Relevance**
2. **Origin and importance**
3. **Specificity**
4. **Order of appearance**

The goal is to determine which declaration should win when multiple CSS rules could style the same element.

---

## 1. Relevance

The process begins with **relevance**.

The browser first filters the CSS rules to find the ones that actually apply to the element being styled. This includes:

- Matching the rule's **selector** against the element.
- Considering **media queries** that may be in effect.

### Media Queries

A **media query** is a CSS technique that applies styles based on characteristics of the device or viewport, such as:

- Width
- Height
- Orientation

For example, a rule inside a media query may only be relevant when the viewport matches the conditions specified by that query.

> **Important:** Before comparing which rule has higher priority, the browser first determines which rules are relevant to the element.

---

## 2. Origin and Importance

After filtering for relevance, the Cascade considers **origin and importance**.

CSS can come from different sources, including:

- **User-agent styles** — the browser's default styles.
- **User styles** — styles provided by the user.
- **Author styles** — styles written by the website or application developer.

The algorithm also considers whether a declaration is marked with `!important`.

### `!important`

Rules marked with `!important` receive higher priority than normal declarations within the cascade.

For example:

```css
p {
  color: blue !important;
}
```

The `!important` marker changes the priority of that declaration compared with a normal declaration.

> **Important:** `!important` is part of the cascade's priority system. It is not simply another form of specificity.

---

## 3. Specificity

After considering origin and importance, the algorithm evaluates **specificity**.

**Specificity** measures how specifically a selector targets an element.

When applicable rules have the same origin and importance level, the rule with the **higher specificity** takes precedence.

### General Idea

A more targeted selector has greater specificity than a more general selector.

For example:

```css
p {
  color: blue;
}
```

targets all `<p>` elements, while a selector that targets a particular class or ID is more specific.

The important idea is:

> **When competing rules are otherwise at the same priority level, the more specific selector wins.**

---

## 4. Order of Appearance

If the competing rules are still equal after the earlier cascade steps, the **order of appearance** determines which rule is applied.

When two rules have the same specificity, the rule that appears **later** in the CSS takes precedence.

For example:

```css
p {
  color: blue;
}

p {
  color: green;
}
```

Both rules:

- Are relevant to the `<p>` element.
- Have the same origin and importance.
- Have the same specificity.

The second rule appears later, so `color: green` wins.

### Why Order Matters

This is why the order in which you write CSS can sometimes affect the final appearance of a page.

---

## 5. Putting the Steps Together

A useful high-level mental model is:

```text
Multiple CSS rules
       ↓
   Relevance
       ↓
Origin & Importance
       ↓
   Specificity
       ↓
Order of Appearance
       ↓
  Winning rule
```

The browser progressively narrows down the competing rules until it determines which declaration should be applied.

---

## Example: Two Rules Targeting the Same Paragraph

Consider this HTML:

```html
<link rel="stylesheet" href="styles.css">

<p>example paragraph</p>
```

The CSS contains two rules targeting the paragraph:

```css
p {
  color: blue;
}

p {
  color: green;
}
```

### What Happens?

Both rules target the `<p>` element, so both are relevant.

They also have the same:

- Origin and importance
- Specificity

The deciding factor is therefore **order of appearance**.

The second rule appears later:

```css
p {
  color: green;
}
```

Therefore, the paragraph's text color will be **green**.

---

## Summary

| Cascade stage | What it determines |
|---|---|
| **Relevance** | Which CSS rules actually apply to the element |
| **Origin and importance** | The priority of the rules based on where they come from and whether they use `!important` |
| **Specificity** | Which selector is more specifically targeted |
| **Order of appearance** | Which rule wins when the earlier factors are equal |

---

## Key Takeaways

- The **Cascade Algorithm** determines which CSS rules are applied when multiple rules target the same element.
- The process begins by filtering for **relevance**.
- The cascade then considers **origin and importance**.
- **Specificity** determines which selector wins when competing declarations are at the same origin and importance level.
- If the competing rules are still equal, **order of appearance** decides the result.
- When two equally specific rules target the same element, the rule written **later** wins.
- In the example, `color: green` wins because the second `p` rule appears after the first one.
