# CSS Combinators

CSS combinators define **relationships between selectors**. They let you select elements based on where they appear in relation to other elements in the HTML document.

Instead of selecting an element only by its tag, class, or ID, combinators let you express relationships such as:

- an element **inside** another element,
- an element that is a **direct child**,
- an element that **immediately follows** another element, or
- an element that appears **later among the same siblings**.

This makes CSS selectors more precise and helps prevent unintended styling.

---

## 1. Descendant Combinator

The **descendant combinator** selects elements that are nested anywhere inside another element.

Its syntax uses a **space** between two selectors:

```css
ancestor descendant {
  /* styles */
}
```

The first selector represents an ancestor, while the second selector represents an element somewhere inside that ancestor.

An ancestor can be:

- a parent,
- a grandparent,
- or any element farther up the document tree.

### Example

```html
<link rel="stylesheet" href="styles.css">

<figure>
  <img src="https://cdn.freecodecamp.org/curriculum/cat-photo-app/relaxing-cat.jpg" alt="Relaxing Cat">
  <figcaption>A relaxing cat with a border</figcaption>
</figure>
```

```css
figure img {
  border: 4px solid red;
}
```

Here:

- `figure` is the ancestor selector.
- `img` is the descendant selector.
- `figure img` means **select every `img` that is inside a `figure`**.

The selected images receive a `4px solid red` border.

### Why It Matters

The descendant combinator is useful when you want to style elements based on their containing element.

For example, if a `figure` contains multiple images:

```html
<figure>
  <img src="cat1.jpg" alt="Cat 1">
  <img src="cat2.jpg" alt="Cat 2">
</figure>
```

then:

```css
figure img {
  border: 4px solid black;
}
```

can target both images.

> **Important:** A descendant does not have to be a direct child. It can be nested at any depth inside the ancestor.

---

## 2. Child Combinator (`>`)

The **child combinator** selects only elements that are **direct children** of another element.

Its syntax is:

```css
parent > child {
  /* styles */
}
```

The `>` makes the relationship more specific than a descendant selector.

### Example HTML

```html
<div class="container">
  <p>First</p>

  <div>
    <p>Second</p>
  </div>

  <div>
    <p>Third</p>
  </div>
</div>
```

There are three `<p>` elements, but they are not all at the same level:

```text
.container
├── p "First"       ← direct child
├── div
│   └── p "Second"  ← deeper descendant
└── div
    └── p "Third"   ← deeper descendant
```

To select only the first paragraph:

```css
.container > p {
  color: blue;
}
```

Only `First` receives the blue text color.

### Descendant vs. Child

Compare these two selectors:

| Selector | What it selects |
| --- | --- |
| `.container p` | All `<p>` elements anywhere inside `.container` |
| `.container > p` | Only `<p>` elements directly inside `.container` |

For example:

```css
.container p {
  color: blue;
}
```

would select `First`, `Second`, and `Third`.

But:

```css
.container > p {
  color: blue;
}
```

selects only `First`.

> **Mental model:** `>` means **"one level down."** A space means **"somewhere down inside."**

---

## 3. Next-Sibling Combinator (`+`)

The **next-sibling combinator** selects an element that **immediately follows** another element and shares the same parent.

Its syntax is:

```css
previous + next {
  /* styles */
}
```

The `+` means:

> Select the element immediately after this element.

### Example

```html
<figure>
  <img
    src="https://cdn.freecodecamp.org/curriculum/cat-photo-app/relaxing-cat.jpg"
    alt="A cute orange cat lying on its back."
  />
  <figcaption>A cute orange cat lying on its back.</figcaption>
</figure>
```

The `<figcaption>` immediately follows the `<img>`:

```text
figure
├── img
└── figcaption  ← immediately after img
```

We can select that `figcaption` with:

```css
img + figcaption {
  border: 4px solid black;
}
```

The `figcaption` receives a `4px solid black` border.

### Why It Matters

The `+` combinator is useful when the styling depends on an element being **immediately next to another sibling**.

> **Important:** The target must be the **immediately following sibling**. If another element comes between the two, the selector will not match that target.

---

## 4. Subsequent-Sibling Combinator (`~`)

The **subsequent-sibling combinator** selects **all matching siblings that appear after** a specified element.

Its syntax is:

```css
previous ~ following-siblings {
  /* styles */
}
```

Unlike `+`, the `~` combinator does **not** require the target to be immediately next to the first element.

### Example

```html
<div class="container">
  <h2>Subheading</h2>
  <p>First paragraph.</p>
  <p>Second paragraph.</p>
  <p>Third paragraph.</p>
  <p>Another paragraph element</p>
</div>
```

The `<h2>` and all four `<p>` elements are siblings because they share the same parent:

```text
.container
├── h2
├── p  ← sibling after h2
├── p  ← sibling after h2
├── p  ← sibling after h2
└── p  ← sibling after h2
```

To select all paragraphs that come after the `h2`:

```css
h2 ~ p {
  color: green;
}
```

All four paragraphs will have green text.

### `+` vs. `~`

The key difference is how many following siblings can be selected:

| Combinator | Meaning |
| --- | --- |
| `A + B` | Select `B` only when it immediately follows `A` |
| `A ~ B` | Select all matching `B` siblings that appear after `A` |

For example:

```html
<h2>Subheading</h2>
<p>First</p>
<p>Second</p>
<p>Third</p>
```

With:

```css
h2 + p {
  color: blue;
}
```

only `First` is selected.

With:

```css
h2 ~ p {
  color: green;
}
```

`First`, `Second`, and `Third` are all selected.

> **Mental model:** `+` means **"the next one."** `~` means **"the ones after it."**

---

# Comparing the CSS Combinators

The four combinators discussed here describe different relationships between elements:

| Combinator | Symbol | Relationship | Example |
| --- | --- | --- | --- |
| Descendant | space | Any matching element nested inside | `figure img` |
| Child | `>` | Direct child only | `.container > p` |
| Next sibling | `+` | Immediately following sibling | `img + figcaption` |
| Subsequent sibling | `~` | Any matching following sibling | `h2 ~ p` |

A useful way to remember them:

```text
A B
│ └── anywhere inside A
└──── A contains B somewhere

A > B
│   └── direct child of A
└────── A

A + B
│   └── immediately after A
└────── A

A ~ B
│   └── any matching sibling after A
└────── A
```

---

## Summary

- **Descendant (` `)** — selects matching elements **anywhere inside** an ancestor.
- **Child (`>` )** — selects matching elements that are **direct children**.
- **Next sibling (`+`)** — selects a matching element that **immediately follows** another sibling.
- **Subsequent sibling (`~`)** — selects **all matching siblings that appear after** another sibling.

### Key Takeaways

1. A **space** allows the target to be nested at any depth.
2. `>` restricts the selection to **direct children**.
3. `+` selects **only the immediately following sibling**.
4. `~` selects **matching siblings that occur later**, even if they are not immediately adjacent.
5. Choosing the correct combinator gives you more precise control over which HTML elements receive a CSS rule.

---

## Mental Model

Think of HTML as a **tree** and CSS combinators as instructions for moving through that tree:

```text
                 ancestor
                    │
          ┌─────────┴─────────┐
          │                   │
      direct child         descendant
          │
       sibling ─── sibling ─── sibling
          ↑           ↑
          │           │
         `+`         `~`
```

The main question to ask when choosing a combinator is:

> **"What is the relationship between the element I want to style and another element?"**

- **Inside at any depth?** → use a space.
- **Directly inside?** → use `>`.
- **Immediately after?** → use `+`.
- **After it, among the same siblings?** → use `~`.

---

## Why CSS Combinators Matter

CSS combinators let you write selectors based on the **structure and relationships of your HTML**, rather than relying only on classes or IDs.

Understanding these relationships makes it easier to create **precise, targeted styling rules** and avoid accidentally styling elements that should remain unchanged.
