# CSS `display`: Block, Inline, and Inline-Block

HTML and CSS elements can behave differently in a page's layout depending on their `display` behavior. Three important values are:

- `block`
- `inline`
- `inline-block`

Understanding the difference helps you control **how elements occupy space, whether they start on a new line, and whether their dimensions can be controlled**.

---

## 1. Block-Level Elements

A **block-level element** takes up the full available width of its container by default.

### How Block Elements Behave

By default, a block-level element:

- Starts on a **new line**.
- Takes up the **full available width** of its parent container.
- Causes the following content to begin on the next line.
- Behaves as though `display: block;` were applied.

Common block-level elements include:

- `<div>`
- `<p>`
- Headings such as `<h1>`–`<h6>`
- `<ol>`
- `<ul>`
- `<section>`

### Example

```html
<p style="border: 2px solid red;">
  First paragraph
</p>

<p>Second paragraph</p>
```

The first paragraph has a red border, making its occupied area easier to see.

The two `<p>` elements do **not** appear on the same line because paragraphs are block-level elements by default. Each paragraph occupies the available width of its container, which in this example is the `<body>`.

### When to Use Block Elements

Block-level elements are useful when content should **stack vertically**.

They are commonly used to structure larger parts of a webpage, such as:

- Paragraphs
- Sections
- Containers
- Major page-layout regions

> **Mental model:** Think of a block element as a box that takes its own row.

---

## 2. Inline Elements

An **inline element** takes up only as much horizontal space as its content requires.

Unlike a block-level element, it does **not** normally start on a new line. Instead, it flows alongside surrounding text and other inline elements.

### How Inline Elements Behave

By default, an inline element:

- Uses `display: inline;`.
- Remains within the normal flow of surrounding content.
- Takes up only the space needed by its content.
- Does not create a new line before or after itself.

Common inline elements include:

- `<span>`
- `<a>`
- `<img>`

### Example

```html
<p>
  This is a
  <span style="color: red; border: 2px solid green;">red</span>
  word inside a paragraph.
</p>
```

Here, the `<span>` is placed inside the paragraph. Its red text and green border make the element easier to see.

The `<span>` only occupies the space needed for the word **"red"**. It does not push the rest of the paragraph onto a new line.

### When to Use Inline Elements

Inline elements are useful for modifying or representing **smaller pieces of content within a line**, such as:

- Styling part of a paragraph
- Creating links
- Applying a style to a specific word or phrase

> **Mental model:** Think of an inline element as something that sits *inside a line of content* rather than creating its own row.

---

## 3. `inline-block`

CSS also provides `display: inline-block`, which combines important characteristics of both `inline` and `block`.

### How `inline-block` Behaves

An `inline-block` element:

- Behaves like an inline element when positioned in the document flow.
- Can sit beside other inline or inline-block elements.
- Does not automatically start on a new line.
- Allows its **width and height to be controlled**, similar to a block-level element.

This makes `inline-block` useful when you want elements to appear **side by side** while still being able to control their dimensions.

### `inline` vs `inline-block` vs `block`

| Behavior | `inline` | `inline-block` | `block` |
|---|---|---|---|
| Starts on a new line | No | No | Yes |
| Flows alongside other content | Yes | Yes | No |
| Can explicitly control width/height | Generally no | Yes | Yes |
| Default width behavior | Content-sized | Content-sized unless specified | Full available width |

> **Key idea:** `inline-block` gives you **inline positioning with block-like dimension control**.

---

## 4. `inline-block` Example

Consider this HTML:

```html
<link href="styles.css" rel="stylesheet">

<div class="container">
  <span class="inline-block-element element1">Inline-Block</span>
  <span class="inline-block-element element2">Inline-Block</span>
</div>
```

And the CSS:

```css
.inline-block-element {
  display: inline-block;
  width: 150px;
  height: 100px;
}

.element1 {
  background-color: lightblue;
}

.element2 {
  background-color: lightgreen;
}
```

### What Happens?

The `<div>` contains two `<span>` elements.

Normally, `<span>` is an inline element. However, the CSS changes both spans to:

```css
display: inline-block;
```

Each element is then given:

```css
width: 150px;
height: 100px;
```

Because they behave like inline elements for positioning, the two elements can appear **side by side**.

At the same time, because they are `inline-block`, their width and height can be explicitly controlled.

So they combine two useful behaviors:

**Inline-like positioning + block-like dimension control**

---

## 5. What Happens Without `inline-block`?

Now remove only the `display: inline-block;` declaration:

```html
<link href="styles.css" rel="stylesheet">

<div class="container">
  <span class="inline-block-element element1">Span element</span>
  <span class="inline-block-element element2">Span element</span>
</div>
```

```css
.inline-block-element {
  width: 150px;
  height: 100px;
}

.element1 {
  background-color: lightblue;
}

.element2 {
  background-color: lightgreen;
}
```

The `<span>` elements return to their default inline behavior.

As a result, the declared:

```css
width: 150px;
height: 100px;
```

does not control the inline elements in the way it does for `inline-block` elements. The spans instead occupy space based on their content.

### Why This Matters

This example demonstrates why the `display` value matters.

Simply specifying `width` and `height` does not automatically make an element behave like a block or inline-block element. **The element's display behavior determines how those dimensions participate in layout.**

---

## 6. A Simple Mental Model

You can remember the three behaviors like this:

```text
BLOCK
┌──────────────────────────────┐
│ Element                      │
└──────────────────────────────┘
              ↓
        starts a new line


INLINE
Text with [element] inside it
              ↓
      stays within the line


INLINE-BLOCK
Text  [  Element  ] [  Element  ]
              ↓
      stays in the flow
      + has controllable dimensions
```

Another way to think about them:

- **`block`** → "Give me my own row."
- **`inline`** → "Let me fit naturally inside the line."
- **`inline-block`** → "Let me stay in the line, but let me control my box size."

---

## Summary

| Display behavior | Main characteristic | Typical use |
|---|---|---|
| `block` | Starts a new line and fills available width by default | Larger sections and vertically stacked content |
| `inline` | Stays within the current line and uses content-sized space | Small pieces of text and inline content |
| `inline-block` | Stays in the line while allowing width and height control | Side-by-side elements that need explicit dimensions |

## Key Takeaways

1. **Block-level elements** normally start on a new line and take up the available width of their container.
2. **Inline elements** stay within the surrounding content flow and normally take up only the space their content needs.
3. **`inline-block`** combines inline-style positioning with the ability to control dimensions.
4. `display` affects how an element participates in layout.
5. If an element is inline, declaring `width` and `height` does not give it the same dimension behavior as an `inline-block` or block element.
6. A useful mental shortcut is:

   > **`block` = new row**  
   > **`inline` = within the line**  
   > **`inline-block` = within the line + controllable box**
