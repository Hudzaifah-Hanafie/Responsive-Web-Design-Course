# CSS Functional Pseudo-classes

Functional pseudo-classes let you select elements using a condition or relationship expressed inside parentheses. They make selectors more flexible and can reduce repetition.

A regular pseudo-class such as `:hover` or `:focus` selects an element based on a state. A **functional pseudo-class** accepts an argument, usually a selector or selector list, and uses it to decide which elements match.

The four functional pseudo-classes covered in this note are:

- `:is()`
- `:where()`
- `:has()`
- `:not()`

![[04-Functional-Pseudo-classes-Overview.excalidraw]]

## 1. `:is()` — Match Any Selector in a List

Use `:is()` when several different selectors should receive the same styles. It groups alternatives into one selector, so you do not have to repeat the same declarations for each alternative.

### Example: Styling different kinds of buttons

Imagine a page contains:
- A native `<button>` element.
- An `<a>` link styled to look like a button.
- Submit and reset `<input>` elements.

#### HTML

```html
<link rel="stylesheet" href="styles.css" />

<button>Example Button</button>
<a href="#" class="button">Link styled like a button</a>
<input type="submit" value="Submit" />
<input type="reset" value="Reset" />
```

#### Without `:is()`

You must list each selector separately. The hover rule repeats the same list:

```css
button,
a.button,
input[type='submit'],
input[type='reset'] {
  background-color: darkblue;
  color: white;
  border: 1px solid darkblue;
  padding: 10px 20px;
  text-decoration: none;
  border-radius: 5px;
  cursor: pointer;
  display: inline-block;
  margin: 5px;
  font-size: 16px;
  text-align: center;
}

button:hover,
a.button:hover,
input[type='submit']:hover,
input[type='reset']:hover {
  background-color: blue;
  border-color: blue;
}
```

#### With `:is()`

The same alternatives can be grouped inside `:is()`:

```css
:is(button, a.button, input[type='submit'], input[type='reset']) {
  background-color: darkblue;
  color: white;
  border: 1px solid darkblue;
  padding: 10px 20px;
  text-decoration: none;
  border-radius: 5px;
  cursor: pointer;
  display: inline-block;
  margin: 5px;
  font-size: 16px;
  text-align: center;
}

:is(button, a.button, input[type='submit'], input[type='reset']):hover {
  background-color: blue;
  border-color: blue;
}
```

**How to read it:** select an element if it matches `button`, `a.button`, `input[type='submit']`, or `input[type='reset']`. The `:hover` version applies the hover styles to whichever of those elements is currently hovered.

### Why it is useful

- It makes long selector lists easier to read.
- It reduces repetition when the same rule applies to several kinds of elements.
- It keeps related selector alternatives together.

### Specificity note

`:is()` does not add a separate specificity value of its own. Its specificity is the specificity of the **most specific selector in its argument list**. This can matter when two CSS rules compete to style the same element.

## 2. `:where()` — Match a List Without Adding Specificity

`:where()` works much like `:is()`: it matches an element if that element matches one of the selectors in its argument list.

The key difference is specificity:

- `:is()` takes the specificity of its most specific argument.
- `:where()` always has **zero specificity**.

That makes `:where()` especially useful for broad baseline styles or resets that should be easy to override later.

![[05-Is-Where-Specificity.excalidraw]]

### Example: Resetting heading spacing

#### HTML

```html
<link rel="stylesheet" href="styles.css" />

<h1>Page Title</h1>
<h2>Subtitle</h2>
<h3>A point</h3>

<p>Example paragraph.</p>
<p>Example paragraph.</p>
<p>Example paragraph.</p>
```

#### CSS

```css
:where(h1, h2, h3) {
  margin: 0;
  padding: 0;
}
```

**What happens?**

- The selector matches `h1`, `h2`, and `h3`.
- It sets their `margin` and `padding` to `0`.
- It does not match the paragraph elements.
- Because the selector has zero specificity, a later rule targeting a heading directly can override the reset more easily, assuming the cascade's other conditions are equal.

### When to choose `:is()` or `:where()`

| Situation | Better fit | Reason |
|---|---|---|
| Group alternatives into a concise selector | `:is()` | It simplifies a selector list |
| Apply a low-priority reset or default style | `:where()` | Its specificity is always zero |
| Make a selector easier to override | `:where()` | It does not increase specificity |

> **Remember:** `:is()` and `:where()` are similar in what they match. Their important difference is how they affect specificity.

## 3. `:has()` — Select an Element Based on a Related Element

`:has()` selects an element when at least one element matching its argument exists in the relevant relationship.

A useful mental model is: **“Select this element if it has something that matches this condition.”**

This is particularly useful when you want to style a parent based on what it contains. Previously, this kind of parent-dependent styling was difficult to express with ordinary CSS selectors.

### Example: Articles that contain an `<h2>`

#### HTML

```html
<link rel="stylesheet" href="styles.css" />

<article>
  <h2>Subheading</h2>
  <p>Lorem ipsum dolor sit amet.</p>
</article>

<article>
  <h3>A point</h3>
  <p>Lorem ipsum dolor sit amet.</p>
  <p>Lorem ipsum dolor sit amet.</p>
</article>
```

#### CSS

```css
article:has(h2) {
  border: 2px solid hotpink;
}
```

**What happens?**

1. CSS checks each `article` element.
2. `:has(h2)` tests whether that article contains an `h2`.
3. The first article contains an `h2`, so it matches and receives the hot-pink border.
4. The second article contains an `h3`, but no `h2`, so it does not match.

![[06-Has-Not-Selection-Logic.excalidraw]]

### How to read the selector

```css
article:has(h2)
```

Read it as: “Select an `article` element that has an `h2` inside it.”

The condition can be based on the presence of a matching descendant, as in this example. The broader idea is that `:has()` lets the selected element depend on a related element.

## 4. `:not()` — Exclude Elements That Match a Selector

Use `:not()` when you want to select a group of elements while excluding a particular case.

A useful mental model is: **“Select this element, except when it matches this condition.”**

### Example: Style every button except the primary button

#### HTML

```html
<link rel="stylesheet" href="styles.css" />

<button class="primary">Primary Button</button>
<button class="secondary">Secondary Button</button>
<button class="danger">Another Secondary Button</button>
```

#### CSS

```css
button {
  padding: 10px 20px;
  border-radius: 4px;
  cursor: pointer;
  font-size: 16px;
  border: none;
  color: white;
}

button.primary {
  background-color: deepskyblue;
}

button:not(.primary) {
  background-color: grey;
}
```

**What happens?**

- `button` selects all three buttons and gives them their shared base styles.
- `button.primary` selects only the primary button and gives it a deepskyblue background.
- `button:not(.primary)` selects buttons that do not have the `primary` class.
- Therefore, the secondary and danger buttons receive a grey background, while the primary button is excluded from that rule.

### How to read the selector

```css
button:not(.primary)
```

Read it as: “Select a `button` unless it matches `.primary`.”

## 5. Comparing the Four Functional Pseudo-classes

| Pseudo-class | Main question | What it does |
|---|---|---|
| `:is()` | “Does it match any of these?” | Groups selector alternatives |
| `:where()` | “Does it match any of these, with zero specificity?” | Groups alternatives without adding specificity |
| `:has()` | “Does this element have a related match?” | Selects an element based on a related element |
| `:not()` | “Does it *not* match this?” | Excludes elements matching the argument |

### Quick selector-reading practice

```css
:is(h1, h2, h3)
```
Select an `h1`, `h2`, or `h3`.

```css
:where(h1, h2, h3)
```
Select the same heading elements, but contribute zero specificity.

```css
article:has(h2)
```
Select an `article` that contains an `h2`.

```css
button:not(.primary)
```
Select buttons that do not match the `.primary` class selector.

## Summary

- **`:is()`** groups several selector alternatives into one concise selector.
- **`:where()`** behaves similarly to `:is()`, but always contributes zero specificity.
- **`:has()`** selects an element based on whether a related element matches a condition.
- **`:not()`** selects elements that do not match the selector inside its parentheses.

## Key Takeaways

1. Functional pseudo-classes accept arguments inside parentheses.
2. `:is()` and `:where()` are useful for grouping alternatives.
3. The most important difference between `:is()` and `:where()` is specificity.
4. `:has()` is useful when the selection of an element depends on something related to it, such as a child or descendant.
5. `:not()` expresses an exclusion: match the element except when it matches the given selector.

## Mental Model

When reading a functional pseudo-class, focus on the condition inside its parentheses:

- `:is(...)` → **match one of these**
- `:where(...)` → **match one of these, with zero specificity**
- `:has(...)` → **match this element if a related match exists**
- `:not(...)` → **match this, but exclude those**
