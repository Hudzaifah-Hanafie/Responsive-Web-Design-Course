# CSS Input Pseudo-classes

CSS input pseudo-classes let you style form controls according to their current state or attributes. They provide visual feedback as people interact with a form, helping users understand which field is active, which option is selected, and which fields need attention.

A pseudo-class is written by adding a colon and its name to a selector. For example, `input:focus` selects an input while it has focus.

---

## 1. Interaction Pseudo-classes

These pseudo-classes respond to how a user interacts with a form control.

### `:focus` — The Currently Active Field

The `:focus` pseudo-class selects an element that currently has focus. For a text input, this usually happens when the user clicks the field or moves to it using the keyboard.

It is useful for making the active field easy to identify while the user is typing.

**HTML**

```html
<link rel="stylesheet" href="styles.css" />

<form>
  <input type="text" />
</form>
```

**CSS**

```css
input:focus {
  border: 2px solid crimson;
  outline: none;
}
```

When the input receives focus, its border becomes crimson.

> **Accessibility note:** A visible focus indicator helps keyboard users understand where they are on the page. If you remove the browser's default outline, provide another clear focus style—as this example does with a colored border.

### `:hover` — The Pointer Is Over the Field

The `:hover` pseudo-class selects an element while the user's pointer is positioned over it.

It can provide a visual hint that an input is interactive.

**HTML**

```html
<link rel="stylesheet" href="styles.css" />

<form>
  <input type="text" />
</form>
```

**CSS**

```css
input:hover {
  background-color: orange;
}
```

When the pointer moves over the input, its background changes to orange.

**When to use it:** Use `:hover` for supplementary feedback. Do not rely on it as the only way to communicate an input's state, because touchscreens do not have the same pointer-hover interaction.

### `:checked` — A Checkbox or Radio Button Is Selected

The `:checked` pseudo-class selects a checkbox or radio button when it is selected.

It is useful for showing which option the user has chosen. It can also be used when building a custom-looking checkbox.

**HTML**

```html
<link rel="stylesheet" href="styles.css" />

<form>
  <label>
    Agree <input class="checkbox" type="checkbox" />
  </label>
</form>
```

**CSS**

```css
.checkbox {
  appearance: none;
  width: 18px;
  height: 18px;
  border: 2px solid #ccc;
  border-radius: 4px;
  display: inline-block;
  position: relative;
  cursor: pointer;
  transition: all 0.25s ease;
  vertical-align: middle;
}

.checkbox:hover {
  border-color: #888;
}

.checkbox:checked {
  background-color: #4caf50;
  border-color: #4caf50;
}

.checkbox:checked::after {
  content: "";
  position: absolute;
  left: 4px;
  top: 0px;
  width: 5px;
  height: 10px;
  border: solid white;
  border-width: 0 2px 2px 0;
  transform: rotate(45deg);
}

.checkbox:focus {
  outline: 2px solid #90caf9;
  outline-offset: 2px;
}
```

The styles work together as follows:

- `appearance: none` removes the browser's default checkbox appearance so the control can be styled.
- The base `.checkbox` rule sets its size, border, shape, and positioning.
- `.checkbox:hover` changes the border when the pointer is over the checkbox.
- `.checkbox:checked` changes the background and border when it is selected.
- `.checkbox:checked::after` creates a checkmark using a pseudo-element and borders.
- `.checkbox:focus` adds a visible focus indicator.

> **Note:** This example uses CSS properties and pseudo-elements that may be introduced in later lessons. The important idea here is that `:checked` lets CSS apply styles based on whether the checkbox is selected.

## 2. Requirement and Availability Pseudo-classes

These pseudo-classes select controls according to whether they are required or disabled.

### `:required` — A Required Field

The `:required` pseudo-class selects form controls that have the HTML `required` attribute.

A required field must be completed before the browser allows the form to pass its built-in validation and submit.

**HTML**

```html
<link rel="stylesheet" href="styles.css" />

<form action="#">
  <label for="name">Name:</label>
  <input type="text" id="name" name="name" required />

  <label for="email">Email:</label>
  <input type="email" id="email" name="email" required />

  <label for="phone">Phone Number:</label>
  <input type="tel" id="phone" name="phone" />

  <button type="submit">Submit</button>
</form>
```

**CSS**

```css
input:required {
  border: 2px solid orange;
}
```

The name and email fields receive an orange border because they have the `required` attribute. The phone number field does not match the selector because it is optional.

**Why it matters:** Styling required fields can help users recognize which information they must provide. You can also communicate this in text—for example, with a visible “Required” label—rather than relying on color alone.

### `:disabled` — A Field the User Cannot Interact With

The `:disabled` pseudo-class selects form controls that are disabled, usually through the HTML `disabled` attribute.

A disabled input cannot be clicked, focused, or edited by the user.

**HTML**

```html
<link rel="stylesheet" href="styles.css" />

<form>
  <label for="name">Name:</label>
  <input class="text-input" type="text" id="name" name="name" disabled />
</form>
```

**CSS**

```css
.text-input:disabled {
  background-color: lightgray;
  cursor: not-allowed;
}
```

The disabled input receives a light-gray background. The `cursor: not-allowed` value changes the pointer to a symbol that indicates the action is not permitted.

**Important distinction:** `:disabled` selects a control that is actually disabled. It is different from simply making a control look inactive with CSS; visual styling alone does not prevent interaction.

## 3. Form Validation Pseudo-classes

HTML form controls can have built-in validation rules. CSS provides pseudo-classes that let you style controls according to whether their current values meet those rules.

### `:valid` — The Value Meets the Validation Rules

The `:valid` pseudo-class selects a form control whose value satisfies its applicable validation constraints.

For example, an `input` with `type="email"` is checked against the browser's email-format rules.

**HTML**

```html
<link rel="stylesheet" href="styles.css" />

<form>
  <label for="email">Email:</label>
  <input type="email" id="email" name="email" />
</form>
```

**CSS**

```css
input:valid {
  border-color: green;
}
```

When the input's value satisfies its validation rules, its border becomes green.

### `:invalid` — The Value Does Not Meet the Validation Rules

The `:invalid` pseudo-class selects a form control whose value does not satisfy its applicable validation constraints.

**HTML**

```html
<link rel="stylesheet" href="styles.css" />

<form>
  <label for="email">Email:</label>
  <input type="email" id="email" name="email" />
</form>
```

**CSS**

```css
input:invalid {
  border-color: crimson;
}
```

When the input contains a value that does not satisfy the email input's validation rules, its border becomes crimson.

### Comparing `:valid` and `:invalid`

| Pseudo-class | Selects | Example use |
|---|---|---|
| `:valid` | A control whose value meets its validation constraints | Indicate an acceptable value |
| `:invalid` | A control whose value fails its validation constraints | Indicate a value that needs correction |

> **Important:** These pseudo-classes reflect HTML validation constraints; they do not automatically validate every business rule your application may have. For example, `type="email"` checks the value's format, not whether the email address actually exists.

## 4. Other Useful Input Pseudo-classes

The following pseudo-classes are also useful when styling form controls:

| Pseudo-class | What it selects |
|---|---|
| `:autofill` | Input fields that the browser has automatically filled with saved information |
| `:optional` | Form controls that do not have to be filled in; they are not marked `required` |
| `:in-range` | Elements whose values fall within the range set by their range constraints |
| `:out-of-range` | Elements whose values fall outside the range set by their range constraints |

These selectors let you give users additional visual feedback based on browser autofill and input constraints.

---

## Summary

| Pseudo-class | When it matches | Typical purpose |
|---|---|---|
| `:focus` | The element currently has focus | Highlight the field being used |
| `:hover` | The pointer is over the element | Provide pointer-hover feedback |
| `:checked` | A checkbox or radio button is selected | Show the selected option |
| `:required` | The control has the `required` attribute | Identify mandatory fields |
| `:valid` | The value meets applicable validation constraints | Indicate a valid value |
| `:invalid` | The value fails applicable validation constraints | Indicate a value that needs attention |
| `:disabled` | The control is disabled | Show that the control cannot be used |
| `:autofill` | The browser has autofilled the input | Style automatically filled fields |
| `:optional` | The control is not required | Identify fields that may be left empty |
| `:in-range` | The value is within its specified range | Indicate an in-range value |
| `:out-of-range` | The value is outside its specified range | Indicate an out-of-range value |

## Key Takeaways

- **Pseudo-classes select elements based on state or conditions**, allowing CSS to respond to user interaction and form validation.
- Use `:focus` to make the currently active field easy to identify.
- Use `:hover` to provide feedback when a pointer moves over a control.
- Use `:checked` to style selected checkboxes and radio buttons.
- Use `:required` and `:optional` to distinguish mandatory fields from fields that can be left empty.
- Use `:valid` and `:invalid` to reflect whether a value meets the control's HTML validation constraints.
- Use `:disabled` to style controls that users cannot interact with.
- Keep important feedback accessible: do not communicate a field's state through color alone, and preserve a visible keyboard focus indicator.

## Mental Model

Think of input pseudo-classes as **state selectors**. The HTML defines the form controls and their attributes; the browser tracks interaction and validation state; CSS uses pseudo-classes to select controls in those states and change their appearance.

```text
HTML form control
       |
       v
Browser evaluates its state
       |
       +-- User interaction
       |      +-- Pointer over it?  -> :hover
       |      +-- Has focus?        -> :focus
       |      +-- Selected?         -> :checked
       |
       +-- Attributes and validation
              +-- Required?         -> :required
              +-- Disabled?         -> :disabled
              +-- Value acceptable? -> :valid / :invalid
              +-- Within range?     -> :in-range / :out-of-range
       |
       v
CSS applies the matching styles
```
